# Ground truth 樣本

遊戲**只喺培育完成之後**先顯示総合評價点，育成途中冇得對答案。
所以每一條「培育完成」嘅紀錄都係一個校準樣本，用嚟量度同收窄我哋公式嘅誤差。

## 點用

1. 複製 `_template.json.example` → 改名（例如 `2026-01-01-中距離.json`）
2. 填好之後跑：

```bash
node tools/fit-score.js
```

## 欄位

| 欄位 | 必要 | 說明 |
|---|---|---|
| `id` | 建議 | 樣本名，出報告時顯示 |
| `stats` | ✅ | `[速度, 持久力, 力量, 毅力, 智慧]`，培育完成時嘅五維 |
| `total` | ✅ | **遊戲顯示嘅総合評價点**（最重要嘅 ground truth） |
| `rank` | 建議 | 遊戲顯示嘅ランク（會自動核對） |
| `uniqueSkills` | 建議 | `[{ "star": 3, "level": 5 }]`，育成ウマ娘自己嘅固有技能 |
| `inheritedUniqueCount` | 建議 | 繼承固有技能數量（每個固定 180 分） |
| `skills` | 建議 | 非固有技能清單 |
| `skillScore` | 可選 | 想跳過技能計算就直接填技能分總和 |
| `server` / `note` | 可選 | 備註 |

### `skills` 每一項

```json
{ "name": "短距離直線◎", "base": 239, "aptitudes": ["S"] }
```

- `base`：技能圖鑑嘅「基礎評價分」
- `aptitudes`：技能**每個限制條件**對應嘅適性等級，例如短距離技能就填該ウマ娘嘅短距離適性

> 唔肯定 `base` / `aptitudes` 都唔緊要 —— 只填 `name`，我幫你查技能圖鑑補齊。
> 但如果連技能名都唔齊，`skillScore` 就會唔準，誤差就會被污染，報告會標示出嚟。

## 為何需要多過一條

| 目的 | 需要 |
|---|---|
| 驗證總分有冇系統性偏差 | 1–2 條 |
| 判斷 `round` / `floor` 邊個啱 | 3–5 條，五維分布要唔同 |
| **反推完整逐點表（誤差 = 0）** | 覆蓋全部 18 段，報告尾會顯示仲爭邊幾段 |

報告尾嘅「段覆蓋率」會直接話你知仲需要邊種數值範圍嘅樣本。

## 收樣本要點（2026-09-19，實戰記低）

⭐ **最有價值嘅畫面 = 育成終了「賽馬娘詳情」面板**（用戶實測）：同一個面板就有齊
**遊戲自己顯示嘅評價点**（頭像下面，例如 `35,050`）＋ **ランク徽章**（例如 `UD1`）＋
五維 ＋ 適性。⚠️ 唔好用「技能 Pt」當技能分（Pt ≠ 評價分）。

⚠️ **「技能」tab 一屏睇唔晒，一定要捲動**：
- 一屏只見到 **7 行 × 2 欄 = 14 招**，但一條培育完成嘅紀錄通常有 **25–27 招**
  → 要**捲到底**再拍 1–2 張（第 5 條樣本用咗 3 張：頂部 ＋ 捲一次 ＋ 捲到底）。
- 拼清單時**一定要用前後張嘅重疊行對齊**（唔好靠估中間有冇漏），
  拼完之後**再數一次總數**（正常技能 15–22 招 ＋ 固有）。
- ⭐ **用戶提供嘅捷徑**：⭐ **綠色底技能之前嘅全部都係固有技能**
  （實例：`京都賽場○`／`喜歡獨處○` 係綠色，佢哋**前面**嘅 5 招就係固有）。
  → 固有唔喺技能圖鑑 → `fill-ground-truth.js` 會自動歸入「繼承固有 180」，
  所以**唔會**污染普通技能嘅 `base`（見 AGENTS 地雷 #4）。
- 自己嘅固有技能會有 **`Lv`**（例如 `絕對是我 Lv5`）→ 填落 `uniqueSkills`；
  其餘嘅（含 `VICTORY SHOT！`／`Shadow Break` 呢類**唔喺圖鑑**嘅英文名）＝ 繼承固有。
