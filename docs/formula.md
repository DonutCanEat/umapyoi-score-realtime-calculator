# 評價分計算公式（已查證部分）

```
總評價點 = Σ 五維評價點 + Σ 技能評價點
ランク   = 依總評價點查閾值表
```

## 1. 五維（ステータス）

> ## ✅ 已解決：用精確演算法，覆蓋 0–2000
>
> 來源：bwiki「繁中评分计算器」widget 嘅 `五维计算()`（`Widget:繁中评分计算器`）。
>
> ```js
> const koeffi = [0.5, 0.8, 1, 1.3, 1.6, 1.8, 2.1, 2.4, 2.6, 2.8, 2.9, 3, 3.1, 3.3,
>                 3.4, 3.5, 3.9, 4.1, 4.2, 4.3, 5.2, 5.5, 6.6, 6.8, 6.9];  // 每 50 點
> const ovk    = [7.888, 8, 8.1, …, 18.3];                              // 1200 以上每 10 點
>
> v = 屬性值；若 v > 1200 → oval = v − 1200，v = 1200
> v += 1；q = ⌊v/50⌋；r = v mod 50
> result = Σ_{i<q} 50·koeffi[i] + r·koeffi[q]
> 再加 oval 嘅部分，最後 floor
> ```
>
> 實作喺 `src/umascore/tables.js` 嘅 `statPoints()`。
>
> **已驗證**：102→68、502→853、902→2217、600→1143、1200→3841、2000→14280 全部命中，
> 而且 4 隻實機馬嘅ランク（UD3 / UE6 / UF8 / UG2）自動對返。誤差 = **0**。

對應嘅取樣表（回歸測試用）：

| 屬性值 | 0 | 50 | 100 | 150 | 200 | 250 | 300 | 350 | 400 | 500 | 600 | 700 | 800 | 900 | 1000 | 1050 | 1100 | 1150 | 1200 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 評價點 | 0 | 25 | 66 | 116 | 181 | 261 | 352 | 457 | **577** | 847 | 1143 | 1463 | 1808 | 2209 | 2635 | 2895 | 3171 | 3501 | 3841 |

> ⚠️ **400 → 577，唔係 557**。有啲舊社群表（wikiru）寫 557，但用 557 反推會令 500 變成
> 557 而唔係公認嘅 847，所以 557 係打錯。bwiki 表同演算法都係 577。

**驗算**：五維全 600 → 1143 × 5 = **5715**，同 [umsatei](https://umsatei.com/) 預設顯示嘅 1143pt/項完全吻合 ✅

### 2.2 繼承・固有技能

每個**固定 180 分**，唔受係數影響。

### 2.3 非固有技能

```
評價點 = 基礎評價點 × Π(1 + 係數)
```

係數由技能嘅**限制條件**對應嘅適性等級決定；**同一類別內取最大，跨類別相乘**；無條件（通用）技能 ×1.0：

> ✅ **2026-08 用 4 條 ground truth 樣本驗證到誤差 = 0**：
> - `中距離, 長距離` → 兩個都係距離類 → **max**（唔係相乘）
> - `前列, 居中` → 兩個都係腳質類 → **max**
> - `前列, 中距離` → 跨類別 → **相乘**
> - 草地／沙地**唔乘**（測試樣本有「良好場地◎」而仍然 = 0）
>
> 即係 bwiki wiki 文字寫嘅「多個相應(1+係數)相乘」係唔準確嘅，
> 應該跟 widget 嘅 `if` 鏈邏輯。原先照字面相乘會令四條樣本全部超計。

| 適性等級 | 係數 |
|---|---|
| S / A | +10% |
| B / C | −10% |
| D / E / F | −20% |
| G | −30% |

**驗算**：通用白 217 × 1.1 = 238.7 → **239**，同日文 wiki「距離・腳質專用白スキル = 239」吻合 ✅

> 仲需要一個「技能基礎評價點 + 限制條件」嘅本地資料庫（Phase 2 用）。
> 技能圖鑑嘅「評價分」欄可以爬，例如 [bwiki 技能速查表](https://wiki.biligame.com/umamusume/%E6%8A%80%E8%83%BD%E9%80%9F%E6%9F%A5%E8%A1%A8)。

## 4. Ground truth：培育完成先有答案

**已確認**：遊戲**只喺培育完成之後**先顯示総合評價點，育成途中嘅ステータス畫面係冇嘅。
（附帶確認：ステータス面板每個屬性格下面嘅 `／NNNN` 係**屬性上限**，唔係評價點，可以忽略。）

所以流程係：

```
真實總分 = 真實五維分 + 技能分
⇒ 真實五維分 = 真實總分 − 技能分（技能分用已知規則精確算出）
⇒ delta = 真實五維分 − 我哋算出嘅五維分 = 我哋嘅誤差
```

每一條「培育完成」嘅紀錄都係一個 sample，放喺 `data/ground-truth/`，然後：

```bash
node tools/fit-score.js
```

報告會列出每個 sample 嘅誤差、ランク有冇對、`round`/`floor`/`ceil` 邊個最貼、
仲有**段覆蓋率**（話你知仲需要邊個數值範圍嘅樣本先可以反推完整逐點表）。
